# دليل مطور لوحة التحكم ومدير المنصة: إدارة ورفع الكورسات والدروس

> **وثيقة توجيهية رسمية** لمطوري الواجهات ولوحة التحكم (Dashboard Developers) ومدراء إدخال المحتوى بالمنصة (Platform Administrators).

---

## 1. حالات نشر الدروس والكورسات (`LessonStatus`: DRAFT vs PUBLISHED)

### البنية المعتمدة في النظام:
حالة النشر في النظام تتبع نموذج الدروس (`Lesson.status`)، وتأخذ إحدى القيمتين فقط:
- `DRAFT`: مسودة (غير منشورة).
- `PUBLISHED`: منشورة ومتاحة للطلاب.

### ⚠️ قاعدة ظهور الكورسات في تطبيق الهاتف:
- **الكورس لن يظهر في التطبيق إطلاقاً** (سواء في قائمة الكورسات المجانية، الكورسات المدفوعة، أو نتائج البحث) **طالما أن جميع دروسه بحالة `DRAFT`** أو لا يحتوي على دروس بعد.
- لكي يظهر الكورس في الواجهة العامة للطلاب، يجب أن يحتوي على **درس واحد على الأقل بحالة `PUBLISHED`**.
- الكورسات التي كل دروسها `DRAFT` تظهر فقط داخل لوحة التحكم للأدمن والمدرب المسؤول عنها للمعاينة والتجهيز.

```json
// مثال لدرس بحالة مسودة (لا يظهر للطلاب)
{
  "title": "مقدمة المحتوى التمهيدي",
  "status": "DRAFT"
}

// مثال لدرس منشور ومتاح
{
  "title": "المحاضرة الأولى: التأسيس",
  "status": "PUBLISHED"
}
```

## 2. حقل وصف الدرس (`description`) حقل اختياري

- حقل الوصف (`description`) **اختياري تماماً (Optional)** في الـ API وقاعدة البيانات.
- يمكن لمطور لوحة التحكم ترك الحقل فارغاً في واجهة الإدخال.
- عند عدم كتابة وصف للدرس، يجب إرسال قيمته كـ `null` أو عدم تضمينه في الـ Payload (لا تشترط الـ Validation إدخال أي نص).

```json
// درس بدون وصف (صحيح ومقبول تماماً)
{
  "title": "الدرس الأول: بنية الشبكات",
  "description": null,
  "moduleId": 12,
  "status": "PUBLISHED"
}
```

## 3. أولوية تبويب الملفات (فتح ملف PDF مباشرة عند النقر على الدرس)

في تطبيق الهاتف المحمول، يتم تصنيف الدرس كـ **ملف مباشر (`isFileOnly`)** إذا رغب مدير المنصة أن يكون تركيز الدرس بالكامل على المذكرة أو المستند دون تشتيت الطالب بفيديو أو شروحات نصية.

### كيف تجعل الدرس يفتح كملف PDF مباشرة؟
لكي يتعرف التطبيق على الدرس وينقل الطالب فوراً إلى عارض ملفات الـ PDF بمجرد الضغط عليه:
1. **اترك حقل الفيديو (`videoUrl`) فارغاً أو `null`.**
2. **اترك حقل الوصف (`description`) وحقل المحتوى (`content`) فارغاً أو `null`.**
3. **أرفق ملف الـ PDF عبر حقل `pdf` (أو `pdfUrl` / `pdfFiles`).**

> **النتيجة في التطبيق:** بمجرد نقر الطالب على الدرس في قائمة الموديول، يتخطى التطبيق شاشة الشرح ومشغل الفيديو وينتقل مباشرة إلى عارض الـ PDF الخاص بالدرس.

## 4. دليل سريع لمدير المنصة (أنواع الدروس وكيفية رفعها)

| نوع الدرس المطلوب | `videoUrl` | `description` / `content` | الملفات المرفقة (`pdf` / `pdfFiles`) | السلوك في التطبيق |
| :--- | :--- | :--- | :--- | :--- |
| **درس مستند / ملف فقط (File Only)** | `null` (فارغ) | `null` (فارغ) | رابط أو ملف PDF | **يفتح ملف الـ PDF مباشرة للدارس** |
| **درس فيديو وملاحظات** | رابط الفيديو (يوتيوب/سيرفر) | نص الشرح أو الملاحظات | اختياري (ملف إضافي للتحميل) | يفتح مشغل الفيديو مع تبويبات الشرح والملفات |
| **درس قراءة فقط (`isReading: true`)** | `null` (فارغ) | نص المقال أو المحتوى التفصيلي | اختياري | شاشة قراءة متكاملة مع عداد قراءة وتسجيل إتمام |
| **محاضرة بث مباشر (Live)** | رابط التسجيل لاحقاً | محاور اللقاء ورابط الزوم | اختياري | تبويب بث مباشر مع زر الانضمام السريع |

## 6. ملاحظات أمنية وتنظيمية لمدير المنصة

1. **لا تنشر الكورس قبل جاهزية المحتوى:** اجعل الدروس `DRAFT` أثناء التسجيل ورفع المواد، وحوّلها إلى `PUBLISHED` عندما تصبح المادة جاهزة للطلاب.
2. **الكورسات المدفوعة:** جميع حقول الدروس الحساسة (الفيديو، الروابط، الملفات، الوصف) محجوبة تلقائياً عن غير المشتركين، فلا داعي للقلق عند نشر الدروس في الكورسات المدفوعة.
3. **التكاليف والاختبارات:** حل الطالب للاختبار أو التكليف يرصد درجاته فقط، ولا يسجله حاضراً للمحاضرة تلقائياً؛ الحضور مقترن بمشاهدة الدرس أو الانضمام للبث المباشر.

## 7. توثيق حسابات المستخدمين (`Verified Users Endpoint`)

خاصية مخصصة للوحة التحكم لتمكين **المدير / الأدمن (ADMIN أو OWNER فقط)** من توثيق حساب أي مستخدم مباشرة وتفعيل علامة التوثيق (`Verified` / `emailVerified`).

### معلومات الـ Endpoint:
- **المسار:** `PATCH /api/v1/users/:id/verify`
- **الصلاحية المطلوبة (Guards):** `ADMIN` أو `OWNER` فقط (أي دور آخر مثل `STUDENT` يتم رفضه بـ `403 Forbidden`).
- **المعاملات (Params):** `id` هو المعرف الرقمي للمستخدم (User ID).
- **جسم الطلب (Body - اختياري):**
  - لتوثيق الحساب: لا يلزم إرسال شيء في الـ body أو إرسال `{ "verified": true }`.
  - لإلغاء التوثيق: يمكن إرسال `{ "verified": false }`.

### مثال الطلب (cURL / HTTP):
```http
PATCH /api/v1/users/42/verify
Authorization: Bearer <ADMIN_OR_OWNER_TOKEN>
Content-Type: application/json

{
  "verified": true
}
```

### استجابة النجاح (200 OK):
```json
{
  "success": true,
  "message": "تم توثيق حساب المستخدم بنجاح.",
  "data": {
    "id": 42,
    "name": "أحمد محمد",
    "email": "ahmed@example.com",
    "role": "STUDENT",
    "emailVerified": true,
    "createdAt": "2026-10-01T12:00:00.000Z",
    "updatedAt": "2026-10-22T21:50:00.000Z"
  }
}
```

## 8. دليل إدارة ملفات الـ PDF للدروس (Lesson PDFs Management API)

تتوفر لمطور لوحة التحكم طريقتان لإدارة ملفات الـ PDF، يمكنه اختيار الأنسب لواجهته:

### 🌟 الطريقة (1): إرسال الملفات دفعة واحدة أثناء إنشاء أو تعديل الدرس (Recommended)

إذا كانت لوحة التحكم تقوم برفع الملفات مسبقاً إلى السيرفر/CDN، يمكن إرسال مصفوفة الروابط والعناوين مباشرة ضمن جسم طلب إنشاء أو تعديل الدرس:

* **المسار:** `POST /api/v1/lessons` أو `PATCH /api/v1/lessons/:id`
* **نوع المحتوى:** `application/json`
* **الترخيص:** `Bearer Token` (Admin / Owner)

```json
{
  "title": "الدرس الثاني: المتجهات والمصفوفات",
  "description": "شرح مفصل للجبر الخطي",
  "moduleId": 12,
  "status": "PUBLISHED",
  "pdfFiles": [
    {
      "title": "ملخص القوانين والجداول",
      "url": "https://ucarecdn.com/xxx-1/summary.pdf",
      "order": 1
    },
    {
      "title": "تمارين وأسئلة تدريبية",
      "url": "https://ucarecdn.com/xxx-2/exercises.pdf",
      "order": 2
    },
    {
      "title": "حلول التكاليف المنزلية",
      "url": "https://ucarecdn.com/xxx-3/solutions.pdf",
      "order": 3
    }
  ]
}
```

---

### 🌟 الطريقة (2): إدارة ملفات الـ PDF بشكل مستقل عبر Endpoints مخصصة

تتيح للمطور إضافة أو حذف ملفات في أي وقت من شاشة تفاصيل الدرس دون الحاجة لإعادة حفظ الدرس كاملاً:

#### 1. إضافة / رفع ملف PDF جديد للدرس
* **المسار:** `POST /api/v1/lessons/:lessonId/pdfs`
* **الترخيص:** `Bearer Token` (Admin / Owner)

##### الخيار أ: رفع ملف فيزيائي (Multipart / Form-Data):
- **المفاتيح المرسلة في FormData:**
  - `file`: (ملف الـ PDF المرفوع)
  - `title`: "عنوان الملف الذي يظهر للطلاب" *(اختياري - إن تُرك فارغاً يأخذ اسم الملف الأصلي)*
  - `order`: 1 *(اختياري)*

##### الخيار ب: إرسال رابط جاهز (JSON):
- **Content-Type:** `application/json`
```json
{
  "title": "ملف اختبارات سابقة",
  "url": "https://ucarecdn.com/xxx/exams.pdf",
  "order": 2
}
```

##### الاستجابة (201 Created):
```json
{
  "id": 15,
  "lessonId": 45,
  "title": "ملف اختبارات سابقة",
  "url": "https://ucarecdn.com/xxx/exams.pdf",
  "order": 2,
  "createdAt": "2026-10-21T17:45:00.000Z"
}
```

---

#### 2. حذف ملف PDF من الدرس
* **المسار:** `DELETE /api/v1/lessons/:lessonId/pdfs/:pdfId`
* **الترخيص:** `Bearer Token` (Admin / Owner)

##### الاستجابة (200 OK):
```json
{
  "message": "تم حذف ملف الـ PDF بنجاح"
}
```
*(ملاحظة: عند حذف الملف، يقوم الباك إند تلقائياً بتحديث `pdfUrl` للدرس ليشير للملف المتبقي التالي).*

---

#### 3. جلب جميع ملفات الدرس
* **المسار:** `GET /api/v1/lessons/:lessonId/pdfs`
* **الترخيص:** `Bearer Token`

##### الاستجابة (200 OK):
```json
[
  {
    "id": 10,
    "title": "ملخص الدرس الأول",
    "url": "https://ucarecdn.com/xxx/summary.pdf",
    "order": 1
  },
  {
    "id": 11,
    "title": "تمارين وتدريبات",
    "url": "https://ucarecdn.com/yyy/exercises.pdf",
    "order": 2
  }
]
```
