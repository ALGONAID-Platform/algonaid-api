# توثيق الـ APIs الخاصة بالإشعارات العامة وإدارة جلسات الأجهزة (لوحة التحكم)

يوضح هذا المستند كيفية ربط لوحة التحكم (Dashboard) مع الـ Endpoints الجديدة لإرسال الإشعارات الجماعية وإلغاء قفل جلسات الطلاب عند تغيير الهاتف.

---

## 1. إرسال إشعار عام للطلاب المشتركين (Broadcast Notification)

تُستخدم هذه الـ Endpoint من قِبل المعلم أو الأدمن لبث إشعار عام لجميع الطلاب المشتركين في دوراته، أو تخصيص الإشعار لطلاب دورة محددة. الإشعار يظهر في التطبيق كإشعار عام غير مرتبط بدرس أو اختبار، وبأمان تام.

* **الرابط:** `POST /api/v1/notifications/broadcast-my-students`
* **المصادقة:** `Bearer Token` (مطلوبة)
* **الصلاحيات المسموحة:** `ADMIN`, `OWNER`
* **الترويسات (Headers):**
  ```http
  Authorization: Bearer <ADMIN_OR_TEACHER_TOKEN>
  Content-Type: application/json
  ```

### جسم الطلب (Request Body):

#### أ. الإرسال لجميع الطلاب في **كافة الكورسات** الخاصة بالمعلم:
```json
{
  "message": "📢 تنبيه هام لجميع طلابنا الأعزاء: نود إعلامكم بتحديث جدول المراجعة، ونتمنى لكم دوام التوفيق والتميز!"
}
```

#### ب. الإرسال لطلاب **كورس محدد فقط**:
```json
{
  "message": "📢 تنبيه خاص بمشتركي كورس الرياضيات: يرجى حل التكليف الثاني قبل موعد الإغلاق.",
  "courseId": 5
}
```

### الاستجابة المتوقعة (Response):

#### عند النجاح (201 Created):
```json
{
  "success": true,
  "message": "تم إرسال الإشعار بنجاح إلى 120 طالب",
  "recipientsCount": 120,
  "commentId": 481
}
```

#### إذا لم يكن هناك طلاب مسجلون حالياً (200 OK):
```json
{
  "success": true,
  "message": "لا يوجد طلاب مسجلين حالياً في هذه الكورسات",
  "recipientsCount": 0
}
```

#### في حال وجود خطأ في المدخلات (400 Bad Request):
```json
{
  "statusCode": 400,
  "message": [
    "نص الإشعار مطلوب"
  ],
  "error": "Bad Request"
}
```

## 2. إلغاء قفل الجلسة للطالب (Admin Reset Session)

تُستخدم هذه الـ Endpoint عندما يفقد الطالب هاتفه أو يقوم بعمل فورمات له، ويرغب بتسجيل الدخول من هاتف جديد دون أن يمنعه النظام. تقوم هذه الـ Endpoint بإنهاء الجلسة القديمة وإلغاء قفل الحساب فوراً.

* **الرابط:** `PATCH /api/v1/users/:id/reset-session`
* **رابط بديل:** `POST /api/v1/auth/admin/reset-session/:id`
* **المصادقة:** `Bearer Token` (مطلوبة)
* **الصلاحيات المسموحة:** `ADMIN`, `OWNER`
* **المتغيرات (URL Params):**
  * `:id` -> معرّف المستخدم (User ID الخاص بالطالب، مثال: `15`)
* **جسم الطلب (Body):** فارغ (لا يتطلب Body).

### الاستجابة المتوقعة (Response):

#### عند النجاح (200 OK):
```json
{
  "success": true,
  "message": "تم إلغاء قفل الجلسة بنجاح للمستخدم (أحمد علي). يمكنه الآن تسجيل الدخول من جهازه الجديد."
}
```

#### في حال لم يتم العثور على الطالب (404 Not Found):
```json
{
  "statusCode": 404,
  "message": "المستخدم غير موجود",
  "error": "Not Found"
}
```
